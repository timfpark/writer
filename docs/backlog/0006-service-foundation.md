## Story

As a contributor or coding agent, I want a minimal, validated `service/`
folder with its own guide and checks so that service features start from the
boundaries and tooling that
[ADR 0001](../adrs/0001-monorepo-structure.md) set out.

## Context

ADR 0001 places the service's manifest, lockfile, toolchain pin, API contract,
configuration example, prompts, and evaluation cases inside `service/`, and
assigns them to the service's first deliverable. It requires a Cargo workspace
inside `service/`, with focused internal crates under `service/crates/` from
the start. [ADR 0002](../adrs/0002-service-architecture.md) chooses axum on
Tokio, the `writer-server` and `writer-api` crates and their dependency
direction, and a `service/openapi.json` contract emitted by utoipa as OpenAPI
3.1 and checked by a freshness test. If building reveals a flaw in that
decision, amend the ADR in the same pull request.
[ADR 0003](../adrs/0003-webapp-architecture.md#development-server-and-service-access)
has the webapp reach the service through a same-origin proxy, so every API
route lives under `/api/` and the service adds no CORS layer.
[ADR 0004](../adrs/0004-api-conventions.md) sets versioning, path and field
naming, error payloads, and operation ID and tag rules below that prefix, and
names the health endpoint `GET /api/v1/health`.

[Backlog 21](./0021-browser-tests.md) starts the real service for every
browser test run as soon as the workspace shell exists, before the service
stores anything, so the executable must start, answer, and stop reliably on
a port that need not collide with a contributor's running service. This
story's pull request adds the repository's first `Cargo.lock`, which CI's
dependency review job checks for known vulnerabilities in every scope and at
every severity, as
[ADR 0001](../adrs/0001-monorepo-structure.md#continuous-integration)
describes.

## Scope

* Confirm whether Cargo must use an organizational registry proxy before
  adding any crate. If it must, configure it globally in
  `.devcontainer/Dockerfile` beside the npm, pip, and uv proxies, document
  host setup in the root README, and give the `cargo` Dependabot entry a
  proxy `registries` entry as the npm entries have.
* Create `service/` with a virtual workspace `Cargo.toml`, a shared
  `Cargo.lock` and `rust-toolchain.toml`, a health endpoint at
  `/api/v1/health` as ADR 0004 specifies, and an `.env.example` with no real
  values.
* Put the thin `writer-server` executable and the `writer-api` library under
  `service/crates/`, with `publish = false` and the dependency direction ADR
  0002 sets. Create only crates needed by this deliverable.
* Bind `127.0.0.1:8080` by default, and let one environment variable,
  documented in `.env.example` and `service/README.md`, override the port
  while the address stays loopback.
* Add the startup and shutdown smoke test
  [ADR 0002](../adrs/0002-service-architecture.md#testing) assigns to this
  story: start the `writer-server` executable on an overridden port, request
  the health endpoint, send SIGTERM, and require a clean exit.
* Choose dependency versions free of known advisories rather than narrowing
  the dependency review job's scopes or severity.
* Commit `service/openapi.json`, generated by `writer-api`, as the contract of
  record covering the health endpoint.
* Add the `Problem` transport type, map axum's rejections and the router's
  fallbacks to it, test that mapping with synthetic marker text, and add the
  conventions test [ADR 0004](../adrs/0004-api-conventions.md#enforcement)
  describes.
* Add a `service` phase to `tools/check` running formatting, lint, build,
  and tests for every workspace member, plus a contract freshness check.
* Apply ADR 0001's
  [Adding a subsystem](../adrs/0001-monorepo-structure.md#adding-a-subsystem)
  checklist, including `service/README.md`, `service/AGENTS.md` with distilled
  operational rules, Governing decisions, and exact commands, the container
  toolchain pinned to `rust-toolchain.toml`, port 8080 in the devcontainer's
  `forwardPorts`, and a `cargo` Dependabot entry.
* Leave `service/prompts/` and `service/evals/` to
  [backlog 12](./0012-first-pair-writing-agent.md), the first pair-writing
  agent story, rather than creating them empty.

## Acceptance criteria

* [ ] The framework, crates, and contract production match
  [ADR 0002](../adrs/0002-service-architecture.md), the health endpoint and
  error responses follow [ADR 0004](../adrs/0004-api-conventions.md), and
  `service/AGENTS.md` links those two ADRs, ADR 0001, and ADR 0003 under
  Governing decisions.
* [ ] The service workspace contains a thin executable and at least one
  internal library crate, and the gate checks every member.
* [ ] Following `service/README.md`, a request to the health endpoint on
  `127.0.0.1:8080` succeeds on a host and in the development container, and
  setting the port variable moves the service to another loopback port.
* [ ] The smoke test starts the executable, receives a health response, and
  sees the process exit 0 after SIGTERM.
* [ ] The dependency review job passes on this story's pull request.
* [ ] Changing the health endpoint without updating the contract makes
  `tools/check` exit 1 with a message naming the contract.
* [ ] A formatting or failing-test change in `service/` makes `tools/check`
  exit 1, and CI reports `CI result` as failed.
* [ ] The root guides list `service/` as existing and link its guide.

## Prerequisites

None.
